# 5.1. Unit-тестирование — Zelen-VR

Проект: Zelen-VR (модуль «Зелёные насаждения»), ветка `vikor`.

Объект проверки: игровая логика Unity/C# в `Assets/Scripts` и `Assets/Scripts/ZamenaVida`. Исходные файлы **не изменялись**.

## Как проводилось

Исходные `.cs`-файлы проекта были собраны без изменений с минимальными заглушками Unity API (.NET SDK 8.0.318 из поставки Unity Editor 6000.6.10f1). Запускались реальные методыисходного кода: проверялись возвращаемые значения, состояние полей, вызовы событий, логи и Transformation-объектов. Прогон автоматизирован, сырые результаты — в `results_unit.json`.

Ограничение: это логический уровень, а не PlayMode внутри редактора Unity. Физика, рендер и Input System подменены управляемыми заглушками, поэтому поведение в настоящей сцене требует дополнительной проверки в Unity.

## Итог: 115 проверок, 112 PASS, 3 FAIL

Покрытие: 4 зоны из README проекта (библиотека/замена, привязка к рельефу, быстрое замещение, VR-меню) плюс действие над объектом, размеры, поворот, подсветка и обработка неверных настроек.

## Найденные дефекты

Три проверки в группе навигации инвентаря завершились FAIL. Это не ошибка стенда, а поведение метода `DzhoystikNavigatsiyaInventarya.OtkrytPanelZameny`:

1. `U-43` — при смене категории с «Деревья» на «Кусты» ранее открытая панель деревьев остаётся активной: одновременно видны две панели замены.

2. `U-44` — вызов для неподдерживаемой категории оставляет `rezhimZameny = true` и предыдущую панель открытой.

3. `U-45` — вызов с пустым объектом оставляет то же устаревшее состояние.

Рекомендация: в начале `OtkrytPanelZameny` сбрасывать `rezhimZameny` и скрывать обе панели, а затем включать только выбранную. Код проекта не правился — по заданию требовалось только тестирование.
